# BSOD Investigator

**BSOD Investigator** — диагностическая программа для Windows, которая помогает расследовать причины синих экранов смерти (BSOD). Она анализирует дампы памяти через Microsoft CDB/WinDbg, сопоставляет результаты с событиями Windows Event Log, данными драйверов и историей прошлых сбоев.

Проект построен как инженерный инструмент диагностики: программа не просто показывает «подозреваемый файл», а собирает несколько источников доказательств, оценивает уверенность и сохраняет технический контекст для дальнейшего анализа.

**Версия:** 1.6.0  
**Платформа:** Windows 10/11  
**Язык:** Python

> Главный подозреваемый — диагностическая гипотеза на основе собранных признаков, а не окончательное доказательство причины сбоя.

## Что демонстрирует проект

- работу с Windows crash dumps, WinDbg/CDB и Windows Event Log;
- объединение нескольких диагностических источников вместо вывода по одному признаку;
- разделение силы доказательств и качества доступной телеметрии;
- хранение истории в SQLite и защиту от повторного учёта одного сбоя;
- управление внешним диагностическим процессом с тайм-аутами, heartbeat и безопасной отменой;
- проектирование компактных структурированных отчётов для последующего технического анализа;
- встроенные regression/self-tests для критичной логики разбора и оценки.

## Основные возможности

- анализ `Minidump` и `MEMORY.DMP` через Microsoft CDB / WinDbg;
- извлечение BugCheck, exception context, stack, failure bucket и проблемного модуля;
- корреляция дампа со связанными событиями Windows Event Log;
- анализ метаданных сторонних драйверов;
- разделение сильных и косвенных диагностических сигналов;
- история анализов в SQLite;
- fingerprint сбоев для защиты от дублирования результатов;
- телеметрия перед сбоем и исторические связи драйверов;
- раздельные показатели уверенности в виновнике и качества телеметрии;
- структурированные JSON/Markdown-логи для технического анализа и работы с ChatGPT/Codex;
- автоматический запрос UAC при необходимости.

## Установка

### 1. Установите Python

Рекомендуется Python 3.10 или новее для Windows.

### 2. Установите Debugging Tools for Windows

Для полноценного анализа дампов нужен Microsoft `cdb.exe`, входящий в **Debugging Tools for Windows / Windows SDK**.

### 3. Скачайте проект

Скачайте репозиторий через **Code → Download ZIP** и распакуйте его в отдельную папку либо клонируйте через Git:

```bash
git clone https://github.com/zeter1/BSOD-Investigator.git
cd BSOD-Investigator
```

Сторонние Python-пакеты для основной работы программы не требуются. Tkinter входит в стандартную установку Python для Windows.

## Запуск

Самый простой вариант:

```bat
run.bat
```

или напрямую через Python:

```bat
py -3 bsod_investigator.py
```

Если для чтения защищённых дампов нужны повышенные права, приложение запросит их через UAC.

## Как пользоваться

1. Запустите BSOD Investigator.
2. Выберите найденный дамп сбоя или укажите файл дампа вручную.
3. Запустите анализ.
4. Дождитесь завершения CDB/WinDbg и сбора дополнительной информации Windows.
5. Изучите BugCheck, стек, подозреваемые драйверы, уровень уверенности и качество доступной телеметрии.
6. Сравните результат с историей предыдущих сбоев, если она уже накоплена.
7. При сложной проблеме используйте созданные диагностические отчёты для дополнительного разбора.

Для наиболее полезного результата рекомендуется анализировать оригинальный dump-файл и не удалять историю приложения между повторяющимися сбоями.

## Надёжность и диагностика

- общий lock предотвращает параллельный конфликт нескольких анализов;
- вывод CDB отображается потоково;
- используются тайм-аут, heartbeat и отслеживание этапов;
- предусмотрено корректное завершение зависших процессов;
- отдельно фиксируются проблемы с символами WinDbg;
- диагностические файлы сохраняют источник, контекст и traceback;
- повторный анализ одного сбоя не должен искусственно повышать уверенность.

## Конфиденциальность

Crash dump может содержать фрагменты системной памяти. Диагностические отчёты также могут содержать технические пути, имена драйверов и процессов. Перед передачей таких файлов третьим лицам рекомендуется проверить их содержимое.

Репозиторий не содержит пользовательские дампы, локальную историю анализов или рабочие диагностические данные.

Подробнее о безопасной публикации диагностических материалов: [`SECURITY.md`](SECURITY.md).
