# Сборка BSOD Investigator в EXE

`build_exe.bat` предназначен для обычного Windows 10/11. Для сборки не нужно заранее вручную ставить PyInstaller или настраивать отдельное Python-окружение.

## Самый простой способ

1. Скачайте репозиторий и распакуйте его в обычную папку с правом записи.
2. Дважды щёлкните `build_exe.bat`.
3. Дождитесь сообщения `[OK] Ready-to-run EXE created and self-tested.`.
4. Готовый файл находится здесь:

```text
dist\BSOD-Investigator.exe
```

## Что делает build_exe.bat

Скрипт последовательно:

- ищет установленный Python 3;
- если Python отсутствует, пытается автоматически установить Python 3.13 для текущего пользователя через `winget`;
- создаёт изолированную папку `.build-venv`, поэтому системный Python не засоряется build-зависимостями;
- устанавливает проверенную версию PyInstaller 6.22.3 и hooks;
- компилирует исходник и запускает безопасный `--self-test` до упаковки;
- удаляет старые `build/`, `dist/` и `.spec`, чтобы случайно не выдать старый EXE за новую сборку;
- создаёт один оконный `BSOD-Investigator.exe`;
- запускает `--self-test` уже на собранном EXE и возвращает ошибку, если packaged runtime не стартует корректно.

То есть появление файла в `dist/` само по себе не считается успешной сборкой: BAT дополнительно проверяет запакованное приложение.

## Повторная сборка

Просто снова запустите:

```bat
build_exe.bat
```

Старая сборка будет очищена автоматически. `.build-venv` сохраняется между сборками для ускорения; удалить её безопасно — при следующем запуске она будет создана заново.

## Режим для CI

```bat
build_exe.bat --ci
```

В этом режиме BAT не ждёт на `pause` и возвращает корректный exit code для GitHub Actions/Codex.

## Важное отличие: CDB / WinDbg

Сам Python-код и его зависимости упаковываются в EXE. Но полноценный анализ crash dump использует официальный диагностический движок Microsoft — `cdb.exe` из **Debugging Tools for Windows**. Это системный компонент Microsoft, а не Python-пакет, поэтому он намеренно не копируется внутрь EXE как неизвестный redistributable.

Если Debugging Tools уже установлены, BSOD Investigator использует их в обычном режиме. Microsoft документирует установку Debugging Tools for Windows как отдельного компонента Windows SDK/WDK. Для разработки/диагностики это единственная внешняя runtime-зависимость полноценного анализа dump.

## Если сборка завершилась ошибкой

BAT специально останавливается на первой проблеме. Смотрите первое сообщение `[ERROR]` выше него. Частые причины:

- `winget` недоступен и Python ещё не установлен;
- корпоративный proxy/антивирус блокирует `pip`;
- папка проекта защищена от записи;
- антивирус временно блокирует только что созданный unsigned EXE.

Не запускайте EXE из `build/`: конечный артефакт находится только в `dist/`.

## Что можно удалить после сборки

Можно удалить:

- `build/`;
- `.build-venv/`;
- `BSOD-Investigator.spec`.

Для запуска готового приложения нужен только `dist\BSOD-Investigator.exe` плюс установленный Microsoft Debugging Tools for Windows для реального CDB-анализа dump.
