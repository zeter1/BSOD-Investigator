# BSOD Investigator 1.6.0

Windows-приложение для расследования BSOD по crash dump, Windows Event Log, метаданным драйверов и истории предыдущих падений.

## Основные возможности

- анализ `C:\Windows\Minidump` и `C:\Windows\MEMORY.DMP` через Microsoft CDB/WinDbg;
- извлечение BugCheck, параметров ошибки, времени аварии, `IMAGE_NAME`, `MODULE_NAME`, `SYMBOL_NAME`, `FAILURE_BUCKET_ID` и crash stack;
- поиск faulting module по контексту исключения;
- временная корреляция событий Windows с реальным временем BSOD;
- анализ `volmgr`, WER, Kernel-Power, WHEA и связанных событий;
- оценка кандидатов-драйверов только по evidence, связанному с самим падением;
- отдельная классификация сторонних драйверов и Microsoft/WHQL signer;
- получение метаданных драйверов из PE, OEM INF, `Win32_PnPSignedDriver` и `Get-WindowsDriver`;
- SQLite-история анализов;
- crash fingerprint для дедупликации повторного анализа одного сбоя и пары `MEMORY.DMP + Minidump`;
- автоматический repair старой истории без удаления старых записей;
- предаварийный ring-buffer телеметрии;
- мониторинг исторически связанных с BSOD драйверов;
- структурированные логи, рассчитанные на последующий анализ человеком или AI.

## Важно про «виновника»

Программа не считает любой загруженный `.sys` виновником. В scoring используются признаки, непосредственно связанные с crash context: faulting module, `IMAGE_NAME`, `MODULE_NAME`, `Probably caused by`, `SYMBOL_NAME`, `FAILURE_BUCKET_ID` и непосредственный crash stack.

`top_suspect` — диагностический кандидат, а не абсолютное доказательство причины BSOD.

С версии 1.6 отдельно показываются:

- **Уверенность в виновнике** — сила собранных доказательств против конкретного драйвера;
- **Качество телеметрии** — насколько полно удалось собрать диагностический контекст.

## Требования

- Windows 10/11;
- Python 3.10+;
- права администратора для чтения защищённых dump-файлов;
- Debugging Tools for Windows / `cdb.exe` для полноценного анализа dump.

Сторонние Python-пакеты для runtime не требуются. GUI использует Tkinter из стандартной поставки Python для Windows.

## Запуск

```bat
run.bat
```

или:

```bat
py -3 bsod_investigator.py
```

При необходимости программа сама запрашивает повышение прав через UAC.

## Встроенная проверка

```bat
py -3 bsod_investigator.py --self-test
```

Self-test проверяет ключевые сценарии парсинга и scoring, восстановление кодировки Event Log, WER-корреляцию, crash fingerprint, дедупликацию одного падения, repair legacy-истории и telemetry quality.

## Сборка EXE

```bat
build_exe.bat
```

Скрипт устанавливает/обновляет PyInstaller и создаёт:

```text
dist\BSOD-Investigator.exe
```

## Где хранятся данные

Основные пользовательские данные находятся в:

```text
%LOCALAPPDATA%\BSODInvestigator
```

Там могут находиться:

- `history.sqlite3`;
- `config.json`;
- отчёты;
- snapshots;
- runtime logs.

Папка `Логи проблем` по возможности создаётся рядом с программой, а если нет прав на запись — используется LocalAppData.

Эти данные не входят в Git-репозиторий.

## Логи CDB

Для CDB-сеансов сохраняются диагностические данные: команда запуска, live output, статус, heartbeat, длительности стадий и AI-контекст. Это позволяет отличить реальное зависание от долгой загрузки symbols, timeout или ручной отмены.

## Конфиденциальность

Логи могут содержать технические пути, имена драйверов и процессов, версию Windows и имя профиля Windows внутри путей. Crash dump потенциально содержит фрагменты памяти, поэтому перед передачей dump третьим лицам его нужно рассматривать как чувствительный файл.

Публичный GitHub-репозиторий не должен содержать реальные `.dmp`, локальную SQLite-историю, runtime logs и support ZIP пользователя.
