# Поддержка и диагностика

Этот репозиторий опубликован как инженерный проект и портфолио. Если вы нашли воспроизводимую ошибку, создайте GitHub Issue через форму **Сообщить об ошибке**.

## Что приложить к сообщению

Укажите:

- версию приложения или commit SHA;
- версию Windows;
- версию CDB / WinDbg, если проблема связана с анализом dump;
- точные шаги воспроизведения;
- ожидаемое и фактическое поведение;
- небольшой релевантный фрагмент диагностического отчёта;
- повторяется ли проблема на текущей версии проекта.

## Диагностические данные

Рабочие данные приложения находятся в `%LOCALAPPDATA%\BSODInvestigator`. Для расследования обычно полезнее компактный JSON/Markdown-отчёт и сообщения CDB, чем весь каталог приложения.

**Не публикуйте crash dump без проверки.** Dump может содержать фрагменты системной памяти и другие чувствительные данные. Перед публикацией также проверьте пути, имена пользователей, имена процессов и другие идентификаторы.

## Что проверить самостоятельно

```bat
python -m py_compile bsod_investigator.py
py -3 bsod_investigator.py --self-test
```

Если `--self-test` проходит, но проблема воспроизводится только с конкретным dump, CDB, символами или Windows-окружением, обязательно укажите это в Issue: такой случай относится к integration/runtime уровню, а не к базовой syntax/self-test проверке.

## Security

Для потенциальной уязвимости или ситуации, где публикация данных в открытом Issue небезопасна, сначала прочитайте [`SECURITY.md`](SECURITY.md).
